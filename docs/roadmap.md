## Этап 2. Генератор локаций ✅ ЗАВЕРШЁН

Каждый пункт — размер одной сессии с самопроверкой по чек-листу и PASS от
`@reviewer` (код и тесты отдельно). Порядок зависимостей: shared → скелет →
RNG → данж → команда замены → пещеры → UI → параметры → полировка.

Ключевая фича этапа: **сгенерированная карта сразу открывается в редакторе
и дорабатывается кистью/объектами** (пункты 2.5–2.7).

- [x] 2.1 Shared-слой: перенос в `src/shared/tiles.ts` констант и типов,
      нужных двум фичам сразу: `TILE_TYPES`, `EMPTY_TILE`, `TileValue`,
      `TileGrid`, `MAX_MAP_DIMENSION` (`MAP_VERSION` остаётся в editor —
      это concern сериализации). Editor реэкспортирует без изменения
      своего       публичного API. Обновить формулировки про shared в AGENTS.md И
      docs/frontend-guidelines.md синхронно (порог «≥2 потребителя»
      достигнут)
- [x] 2.2 Каркас фичи `generator/`: структура папок, публичный `index.ts`,
      типы `DungeonParams` / `CaveParams` / результат — сетка тайлов
      (`TileGrid` из shared)
- [x] 2.3 Детерминированный PRNG mulberry32: нормализация seed к uint32,
      `createRng(seed)` + `nextInt(n)` без modulo bias; тесты:
      воспроизводимость при том же seed, границы диапазона [0, n)
- [x] 2.4 Данж «комнаты + коридоры»: чистая функция
      `(params, rng) → сетка`; непересекающиеся комнаты, коридоры между
      ними, гарантия связности; тесты: связность flood-fill'ом, отсутствие
      пересечений комнат, комнаты в границах, стены по периметру
- [x] 2.5 Команда `replaceMap` (реализуется в editor, рядом с командами
      тайлов; generator лишь отдаёт `TileGrid`): одна запись истории
      заменяет документ целиком — `{ width, height, tiles }` + АТОМАРНАЯ
      очистка objects; undo одним Ctrl+Z возвращает прежнюю карту вместе
      с объектами. Валидация: размеры в [1..MAX_MAP_DIMENSION], длина
      tiles; невалидный ввод → RangeError до мутации. No-op ТОЛЬКО когда
      итоговый документ идентичен текущему (размеры + сетка + objects
      пусты). Тесты: замена разных размеров, откат, no-op на идентичном
      документе, «сетка совпала, но есть объекты» → замена с очисткой,
      объекты восстановлены undo'м
- [x] 2.6 Генератор пещер (cellular automata): случайный шум → N итераций
      с фиксированным правилом «стена, если ≥5 стен среди 8 соседей,
      иначе пол» → рамка стен по периметру. Тесты: seeded-детерминизм,
      рамка стен, корректные значения тайлов
- [x] 2.7 UI-панель генератора: выбор типа (данж / пещеры), поле seed,
      кнопка «Сгенерировать»; результат уходит через `replaceMap`, после
      чего сбрасывается выделение объекта (иначе Delete бросит RangeError)
      и карта сразу правится кистью. Доступность с клавиатуры; ввод seed
      не должен триггерить хоткеи (guard isEditableTarget уже есть —
      покрыть тестом); отдельный RTL-тест: после генерации нажатие Delete
      при снятом выделении не бросает исключений. RTL-тесты, i18n ru/en
- [x] 2.8 Параметры генерации в панели: размер карты (работает благодаря
      `replaceMap` из 2.5), число попыток комнат, стартовая плотность
      пещер, число итераций сглаживания; контролы + unit/RTL-тесты
      передачи в генератор
- [x] 2.9 Полировка: повтор генерации тем же сидом даёт ту же карту
      (кнопка «Ещё раз»; воспроизводимость = фикс. код + фикс. параметры —
      зафиксировать в README алгоритмов `generator/README.md`),
      вынос повторяющихся проверок в чек-лист

## Этап 3. Гексагональная сетка ✅ ЗАВЕРШЁН

Каждый пункт = одна сессия с чек-листом и двойным ревью. Порядок:
модель → математика → рендер → инструменты → UI.

Ключевые решения:
- **Параметризованный layout** (матрица ориентации Red Blob Games): одна
  формула для flat-top и pointy-top, ориентации как данные. Иерархии
  классов нет.
- **Оси**: канонические координаты модели остаются offset (`y*width+x`);
  axial используется только внутри hex-математики. В 3.2 фиксируются
  конверсии offset↔axial для каждой ориентации (odd-r / odd-q) и
  property-тест `pixelToCell(cellCenter(c)) === c` по всем клеткам.
- **cellSize для гекса** = радиус описанной окружности; границы канвы и
  PNG-экспорта считаются через geometry-bounds функцию, а не `w*cellSize`.

- [x] 3.1 Модель и миграция: `gridType: 'square' | 'hex-flat' | 'hex-pointy'`
      в MapModel и `createEmptyMap(width, height, gridType='square')`;
      `MAP_VERSION` 1→2; io принимает version ∈ {1,2} (v1 → gridType
      'square'), >2 и невалидный gridType → ошибка загрузки (MapLoadError —
      конвенция io); serializeMap пишет gridType; `replaceMap`: gridType в
      предикате no-op, поле опционально с дефолтом 'square' (генераторы
      отдают квадрат). Тесты: roundtrip v1/v2, миграция файла без gridType,
      смена только gridType меняет документ
- [x] 3.2 Hex-математика `src/shared/hex.ts`: параметризованная
      ориентация (матрица f²/b из Red Blob Games), pixelToCell (axial +
      cube-round), cellCenter, cellCorners; конверсии offset↔axial
      (odd-r для pointy, odd-q для flat — зафиксировать); property-тест
      round-trip по всем клеткам тестовой карты + known-answer точки
- [x] 3.3 Рендер и границы: renderMap рисует полигоны клеток по geometry
      (вместо прямоугольной ветки), culling видимости через hex-bounds,
      позиционирование объектов через cellCenter; strokePreview и
      cellHighlight переходят на polygon клетки; **pngExport переводится на
      geometry-bounds** (габариты гексов шире/выше w·cellSize — иначе экспорт
      молча обрезает края; лимиты пересчитываются от фактических границ);
      тесты fakeCtx (полигон клетки, смещения, отсечение, полнота покрытия
      крайних клеток в экспорте)
- [x] 3.4 Инструменты: useCellFromEvent/useHoverCell получают gridType в
      аргументах (сигнатуры меняются, потребители useTerrainBrush/
      useObjectTools наследуют hit-test автоматически); интеграционные
      тесты: клик красит гекс, drag-штрих по гексам, объект ставится в
      центр гекса
- [x] 3.5 UI и документ: выбор типа сетки — элемент управления уровня
      документа (панель инструментов), диспатчит НОВУЮ команду
      `setGridType` (метаданные: тайлы и объекты сохраняются, одна запись
      истории, no-op при неизменном типе). Генераторы пока поддерживают
      только `'square'`: при не-square сетке ОБЕ кнопки генерации
      («Сгенерировать» и «Ещё раз») задизейблены с подсказкой — покрыть
      RTL-тестом disabled-состояния (ограничение задокументировано в
      roadmap и README генератора). RTL-тесты, i18n ru/en
- [x] 3.6 Полировка: формат строки координат — чистая функция
      formatCoords(cell, gridType) (offset для квадрата, axial q/r для
      гексов) + unit-тесты; README по формулам и ориентациям
