# Чертоги подземелий (dungeon-halls)

Веб-редактор батлмапов для D&D и других НРИ: построение помещений фигурами,
процедурная генерация локаций и ручная доработка.
Личный проект, локальный запуск без бэкенда. Возможна публикация в будущем.

## Идея

Существующие инструменты (Inkarnate, Dungeondraft, DungeonFog) недоступны из
региона автора или нестабильны, и не позволяют комбинировать генерацию с
ручной доработкой. Этот проект даёт обе возможности:

- строить помещения фигурами (прямоугольники, правильные многогранники)
  с векторными границами и автоматическими стенами;
- расставлять объекты (мебель, кусты, факелы и т.п.);
- генерировать случайные локации (комнаты+коридоры, пещеры);
- дорабатывать сгенерированное вручную — ключевая фича.

Пользователь №1 — сам автор. Многопользовательность и облако не нужны,
пока явно не запрошены.

## Стек

| Слой     | Технология |
|----------|------------|
| Frontend | React 19 + TypeScript, сборщик Vite |
| Стили    | CSS Modules (`*.module.css`, работает в Vite из коробки) |
| Canvas   | HTML5 Canvas 2D (рендер карты), при росте нагрузки — PixiJS |
| i18n     | react-i18next, языки RU + EN |
| Тесты    | vitest (+ React Testing Library, jsdom) |
| Линт     | oxlint (быстрый, конфиг `.oxlintrc.json`) + Prettier (форматирование) |
| Backend  | Нет. Каркас под FastAPI в `backend/` — создаём только при необходимости |
| Данные   | Проекты карт — JSON-файлы на диске; настройки UI — localStorage |

## Структура

```
frontend/src/
  app/        оболочка приложения: панели, меню, i18n
  config/     конфигурационные константы (размеры карты, лимиты)
  editor/     canvas-движок: векторная модель, рендер, инструменты, undo/redo, save/load
    model/    MapModel v6: TerrainRegion, WallSegment, Door, StairsPolygon, MapObject, MapLight;
              regions.ts/wallSegments.ts/doors.ts/stairs.ts, autoWalls.ts, commands.ts, io.ts, objects.ts, lights.ts
    render/   векторный рендер: renderMap (регионы/лестницы/точечная сетка/объекты/стены/двери/свет),
              geometry.ts, regionPreview, cellHighlight, ghostPreview, colors, sprites/
    tools/    инструменты: regions (rect/polygon), regionCommit, autoWalls-коммит,
              wall/door/object/light, generatorAdapter, pngExport
  generator/  процедурная генерация локаций (клеточная сетка → адаптер в регионы)
  shared/     общие константы и типы фич: tiles.ts — палитра тайлов, point.ts — геометрия, id.ts — идентификаторы
backend/      заглушка, пустой до появления серверных задач
docs/         roadmap.md — план развития
.opencode/skills/  скиллы opencode для этого репозитория
```

Архитектурные правила:

- Frontend и backend СТРОГО изолированы: `frontend/` — самодостаточное SPA
  и единственный рантайм сегодня; `backend/` — отдельный сервис на Python,
  который не создаётся и не изменяется без явной задачи. Код между ними не
  шарится, общих типов/утилит нет; единственная будущая точка связи — HTTP API.
- Модель данных карты — **векторная** (MapModel v6): регионы покрытия
  (`TerrainRegion[]` — полигоны с типом ландшафта), стены (`WallSegment[]` —
  ломаные с телом: авто — замкнутый контур, ручная — открытая), двери
  (`Door[]` — самостоятельные проёмы: отрезок `a`–`b` + угол створки
  `openAngle`), лестницы (`StairsPolygon[]` — контуры-оверлеи), объекты
  (`MapObject[]`), источники света (`MapLight[]`).
  НИКАКИХ клеточных массивов (`Uint8Array`) и рёбер (`WallEdge` N/E/S/W).
- Рендер отделён от модели: модель можно сериализовать в JSON без DOM/Canvas.
- Границы карты — настраиваемые константы в `src/config/map.config.ts`
  (`DEFAULT_MAP_WIDTH`, `DEFAULT_MAP_HEIGHT`, `MAX_MAP_SIZE`).
- Сетка только квадратная (supports grid-aligned placement of objects).
  Гексагональная сетка удалена.
- UVTT-экспорт удалён (не используется автором).
- Паттерны проектирования фронтенда: см. `docs/frontend-guidelines.md` —
  читать обязательно перед любой работой с кодом `frontend/`.

## Команды

Все команды выполнять в `frontend/`:

```powershell
npm run dev        # dev-сервер (http://localhost:5173)
npm test           # тесты vitest (watch)
npm run test:ci    # тесты один прогон
npm run lint       # oxlint
npm run format     # Prettier (записывает файлы)
npm run build      # production-сборка в dist/ (включает проверку типов tsc)
```

## Конвенции кода

- TypeScript strict, `any` запрещён, `enum` запрещён (union-типы / `as const`).
- Функциональные компоненты + хуки, без классов.
- Именование файлов: `PascalCase.tsx` для компонентов, `camelCase.ts` для остальных.
- CSS Modules для стилей компонентов, глобальные переменные — в `:root`.
- Комментарии только там, где «почему», а не «что».
- Перед коммитом: `npm run lint && npm run test:ci`.

## Git-процесс

- Основная ветка — `main`. На каждый этап создаётся ветка `stage/<номер>`
  (например `stage/14`); работа этапа ведётся только в ней.
- Слияние этапа в `main` (через `--no-ff`) — только при выполнении ВСЕХ условий:
  1. Новый функционал покрыт тестами.
  2. Все тесты успешно проходят.
  3. Пройдено ревью нового кода И отдельно ревью тестов.
  4. Каждое ревью выполняется отдельным вызовом ревьюера.
  5. При неуспешном ревью по любому пункту — исправить и пройти заново;
     максимум 5 попыток на каждое из ревью.
  6. Проверки всегда запускать в первую очередь тестами
     (`npm run test:ci`), затем lint, затем build.
  7. После пяти неуспешных попыток любого ревью — остановиться и вывести
     автору полные результаты проверок; решение о дальнейших доработках
     принимает автор.

Что умеет редактор сейчас:
- **Построение фигурами**: прямоугольник и правильный N-угольник (3..12)
  с заливкой выбранным покрытием; ластик области.
- **Авто-стены**: точная граница покрытия (`polygon-clipping`), регионы
  наносятся по zOrder («верхний побеждает»), `empty` вырезает дыры; один
  `WallSegment` на замкнутый контур; диагонали без клеточной «лесенки»;
  покрытие базовых регионов кэшируется; чекбокс «Авто-стены» с персистом;
  ручной инструмент стены (привязка к характеристическим точкам клетки) для
  перегородок.
- **Двери (v6)**: самостоятельный проём `{ id, a, b, openAngle, imageId }`
  (не привязан к стене); инструмент в 2 клика (начало/конец; на стене — вдоль
  стены, иначе свободная), проём вырезает стену с зазором 1/6 клетки; клик по
  двери циклит угол створки, правый клик удаляет; текстура из каталога.
- **Лестницы**: инструмент в 3 клика (начало → база → дальний край; 4-я
  вершина — зеркало относительно серединного перпендикуляра к базе), снап
  0.5 и живое превью; клик выделяет, Delete/правый клик удаляет; рендер —
  контур + ступени перпендикулярно оси, без заливки.
- **Объекты**: каталог-реестр, категории, поиск, element-images с персистом,
  rotation/scale, доступные размеры, ghost preview.
- **Свет**: источники с радиусом и цветом.
- **Рендер**: векторные регионы (заливка; в режиме спрайтов — тайлинг, включая
  пул вариантов текстуры с детерминированным выбором по клетке), лестницы
  (контур + ступени), точечная сетка, объекты, стены с телом, двери, свет.
- **Сетка и снап**: точечная сетка (углы покрытых клеток, canvas + SVG/PDF из

- **Экспорт**: PNG, SVG (векторный), многостраничный PDF (jsPDF ленивым чанком).
- **Сохранение/загрузка** JSON (формат v6, миграций нет).
- **Генератор**: данжи и пещеры (клеточная сетка → адаптер в регионы).
- **Undo/redo**, рейл-навигация по разделам, горячие клавиши
