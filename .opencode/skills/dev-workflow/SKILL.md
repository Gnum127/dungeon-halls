# Dev Workflow — Чертоги подземелий

## Контекст

Веб-редактор батлмапов для D&D. Весь код во `frontend/` (React + TS + Vite),
бэкенда нет. Главный источник правды о проекте — `AGENTS.md` в корне репозитория.

**Состояние (обновлять по мере продвижения):**
Этапы 1–18 завершены. Этап 15 (схема v6): покрытие painter-order, авто-стена =
один замкнутый контур, двери-проёмы (`a`/`b`/`openAngle`), лестницы-сущности

## Перед началом работы

1. Прочитай `AGENTS.md` (стек, конвенции, архитектурные правила, Git-процесс).
2. Перед работой с кодом `frontend/` прочитай `docs/frontend-guidelines.md`
   (паттерны обязательны: однонаправленный поток, векторная модель v6,
   слои app/config/editor/generator/shared; исключение composition-root для EditorPage).
3. Открой `docs/roadmap.md` — план этапов 1–18 выполнен; новые задачи —
   из бэклога, если пользователь не указал иное.
4. Этап 18 (лестницы в 3 клика) завершён (18.1–18.6).
5. Работа ведётся в ветке этапа (`stage/18`); слияние в `main` —
   только после выполнения всех условий «Git-процесса» в AGENTS.md.

## Команды (выполнять в `frontend/`)

```powershell
npm run dev        # dev-сервер http://localhost:5173
npm run test:ci    # тесты, один прогон (запускать ПЕРВЫМ)
npm run lint       # oxlint
npm run format     # Prettier
npm run build      # сборка + проверка типов tsc
```

## Перед завершением задачи

1. Прогони проверки В ПОРЯДКЕ: тесты → lint → build (в `frontend/`).
2. Пройди `docs/quality-checklist.md` по затронутым разделам и исправь
   найденное в той же сессии. Для векторной модели — секция «Векторная модель».
   Для генераторов — секция «Генераторы».
3. Для значимых изменений прогони ревью по инструкциям
   `.opencode/agents/reviewer.md` (как сабагент — `subagent_type: "general"`
   с этими инструкциями). Отдельно ревью кода и ревью тестов. При FAIL
   исправь замечания и повтори — не более 5 вызовов на каждый тип ревью;
   после пятого FAIL остановись и сообщи автору.
4. Отметь закрытый пункт roadmap `[x]`.

Коммит делай только по явной просьбе пользователя. Сообщение коммита —
короткое, в повелительном наклонении («Add rect region tool», без точки в конце).

## Правила кода

- TypeScript strict, `any` запрещён; файлы компонентов `PascalCase.tsx`, остальные `camelCase.ts`.
- Стили — CSS Modules (`*.module.css`), цвета через переменные из `src/index.css`;
  inline-стили только для динамики canvas и data-driven значений палитры.
- Тексты интерфейса — ТОЛЬКО через i18n (`useTranslation`), ключи добавлять
  сразу в `ru.json` и `en.json`. Русский текст в JSX — ошибка.
- Модель карты не зависит от DOM/Canvas; команды иммутабельны, no-op не пишут историю.
- Комментарии — только «почему», не «что».
- Размеры карты по умолчанию — из `src/config/map.config.ts`.

## Установленные паттерны (следуй им)

- **Формы**: чистый `parseXxxForm(state)` рядом с компонентом (не экспорт
  из .tsx), строгий парсинг (пустое/hex/exponent → null); кнопка блокируется
  до dispatch; авторитетная валидация остаётся в домене.
- **Pointer-инструменты**: хуки возвращают `handlers`, объединяются через
  `mergePointerHandlers()` — НИКОГДА не спредить два набора подряд
  (второй затирает первый).
- **Общий хелпер события**: `useCellFromEvent(canvasRef, viewportRef)` —
  параметр `ClientPoint = Pick<…,'clientX'|'clientY'>`, не полный event.
- **Refs в событиях**: чтение `ref.current` только внутри обработчиков/эффектов;
  «latest ref» паттерн обновляется через useEffect, не в рендере.
- **Тесты**: интеграционные тесты должны быть дискриминирующими (ловить
  конкретную регрессию, см. stale-id тест EditorPage); стабы jsdom
  (ResizeObserver, matchMedia) живут в `src/test/setup.ts`; язык i18n в
  тестах зафиксирован en там же.
- **Известные ловушки vitest**: `fireEvent.pointercancel` отсутствует —
  собирать через `Object.assign(new Event('pointercancel'), {...})`.

### Новые паттерны (этапы 14–17, векторная модель v6)

- **Регионы**: `TerrainRegion.polygon` — массив `Point[]` (float-координаты
  в клетках), замкнутость обеспечивается при рендере (`closePath`), не в данных.
  `zOrder` — автоинкремент при `addRegion`: `max(existing) + 1`. Покрытие —
  painter-order: регионы наносятся по `zOrder`, `empty` вычитает (этап 15).
- **Стены**: `WallSegment.points` — ломаная в float-координатах. Авто — один
  замкнутый контур (`points[0] === points[last]`), ручная — открытая ломаная.
  Тело — утолщение от осевой на `thickness * cellSize`; целый замкнутый контур
  рисуется одним путём (`closePath`/`Z`) со скруглёнными стыками, открытая
  ломаная — круглыми концами. Единый источник прогонов — `wallRuns(wall, doors,
  DOOR_GAP_CLEARANCE)` в `render/geometry.ts`: проём двери вырезает интервал +
  зазор 1/6 клетки, разрезанный контур становится открытыми прогонами.
- **Двери (v6)**: `Door { id, a, b, openAngle, imageId }` — самостоятельный
  проём: закрытая створка лежит на отрезке `a`–`b`, открытая повёрнута вокруг
  петли `a` на `openAngle` (0 = закрыта, знак = сторона); `doorLeafEnd`;
  инструмент в 2 клика (`doorEndpoints`: на стене — вдоль стены, иначе
  свободная, длина кратна 0.5); цикл кликом `+A → −A → 0`
  (`cycleDoorOpenAngle`). Дверь НЕ привязана к стене.
- **Лестницы (v6)**: `StairsPolygon { id, polygon }` — оверлей без заливки и
  авто-стен; ступени — `stairsStepSegments` (перпендикулярно оси), общие для
  canvas и SVG/PDF. Инструмент в 3 клика (`stairsVertices`: 4-я вершина —
  зеркало относительно серединного перпендикуляра к базе), снап 0.5; клик
  выделяет (`stairsHitTest`), Delete/правый клик удаляет.
- **Псевдорандом текстур**: `shared/random.ts` — собственный целочисленный хеш
  `hashFromCoords(x, y)` (`Math.imul`-микс; без зависимости от `generator/`),
  `pickIndexFromCoords(x, y, len)` = `hash % len`. Пул — `tileTextures[tile].pool`
  в манифесте текстур (опционально); рендер предпочитает пул одиночному `path`,
  вариант выбирается по индексу ТЕКСТУРНОЙ плитки (args — номера плиток `col`,
  `row`, а не координаты в клетках).
- **Авто-стены**: ОДНА составная команда `addRegionWithWalls`, не две отдельных
  (иначе undo в два шага). Реализация (`model/autoWalls.ts`): точная граница
  union'а непустых регионов через boolean-операции `polygon-clipping`
  (union, затем difference на `empty`-регионах = дыры ластика); диагонали без
  клеточной «лесенки». id рёбер детерминированы по координатам → двери на
  неизменных рёбрах переживают пересборку (`replaceWallLayer` сохраняет ручные
  стены). Живое превью (`computePreviewWalls`) объединяет кэш базового покрытия
  (`WeakMap` по `model.regions`) с одним строящимся регионом — без полного
  пересчёта на pointermove. Инструмент стены (ручной) — для перегородок, шаг сетки 0.5
  клетки: `round(worldCoord * 2) / 2`.
- **Слои рендера** (порядок снизу вверх): фон → регионы (по zOrder) →
  лестницы → сетка → объекты → стены (тело + контур) → двери → свет.
- **Сетка (этап 20)**: `model/coverage.ts` — `coverageGridPoints` (углы
  покрытых клеток), `allGridPoints` (все углы диапазона), `gridPoints` →
  `{ covered, empty }` (покрытие считается один раз; единый источник canvas/SVG).
  Свободное поле — тусклые уменьшенные точки (`EMPTY_GRID_POINT_COLOR`).
  Полигон-инструменты клампят вершины к границам карты (`clampPolygonToGrid` в
  `tools/regions.ts`) и НЕ коммитят вырожденный/самопересекающийся полигон
  (`isCommittablePolygon`); `regularPolygonPoints` принимает границы.
- **Инструменты и нижняя плашка (этап 22)**: инструмент выбирается на
  `BottomBar` (курсор/панорама/прямоугольник/многогранник/лестница/дверь);
  боковая панель «Ландшафт» — параметры активного инструмента (`ToolParams`),
  `RegionTools` удалён. Старт — `{ type: 'cursor' }`; `select` заменён на
  `cursor`. Выделение/перемещение/удаление объектов — `useCursorTool` (активный
  только при `cursor`), размещение — `useObjectTools` (только `object`). Пан:
  средняя кнопка всегда, ЛКМ — в режиме `pan` (`useMiddleButtonPan` с опцией
  `leftButton`). Свет и ручная стена — скрытые инструменты (код сохранён).

- **Float-объекты (этап 23)**: `MapObject.x/y` — float в мировых клетках,
  левый-верхний угол (не центр клетки, не привязка к сетке). `objectFootprint`
  даёт `{x,y,w,h}` в клетках (w/h из `scale`); `isFootprintFree`/`rectsOverlap` —
  пересечение float-прямоугольников; `footprintInBounds` проверяет только origin
  (`x,y ≥ 0`), свисание за правый/нижний край разрешено. Геометрия hit-test и
  рендера — из левого-верхнего: `obj.x*cellSize`, центр `+w/2`, поворот вокруг
  центра. Размещение (`useObjectTools`) и ghost-превью — по мировой float-точке
  (`useWorldPointFromEvent`); рендер объектов — ПОСЛЕ точечной сетки (поверх).
  `footprintCells`/`isCellOccupied` удалены; в `useCursorTool` — float-драг и
  Shift-снап 0.5.

- **Текстурный пайплайн (этап 24)**: манифест `public/sprites/manifest.json` v2 —
  `tileTextures: { tile: { path, size, pool? } }` (бесшовные текстуры, тайлятся
  шагом `size` пикселей, под сеткой, клип по полигону) и
  `objectTextures: { kind: { path } }` (растягиваются на footprint, поверх сетки).
  Загрузчик `render/sprites/loader.ts` (`loadTextureManifest`/`loadElementManifest`/
  `loadTextures`), хук `hooks/useTextureAtlas.ts`. Атлас → `TextureRenderContext`
  (`textures`) в `CanvasView`/`MapFileActions`, дальше в `renderMap`/PNG-экспорт.
  Приоритет текстуры объекта: element-image override → `objectTextures` →
  `defaultImage` → цвет. `element-images` остаются для дверей и явного выбора.
  Режима «цвета/спрайты» нет — `RenderModePicker`/`renderMode.ts` удалены.

- **Удаления (этап 14)**: код, содержащий `gridType`, `hex`, `vtt`, `uvtt`,
  `WallEdge`, `WallSide`, `normalizeEdge`, `edgeKey`, `Uint8Array` в модели
  тайлов — выпилить полностью. Старые тесты удалённого функционала — удалить.
