# Экспорт Universal VTT (.uvtt)

Кнопка **Export UVTT** (рядом с Export PNG) собирает файл формата
Universal VTT — ZIP-архив из `map.json` и PNG-рендера карты. Файл понимают
Foundry VTT (модуль Universal Battlemap Importer) и Roll20 (Pro).

## Состав архива

| Запись                  | Содержимое                              |
| ----------------------- | --------------------------------------- |
| `map.json`              | метаданные: сетка, стены, порталы, свет |
| `dungeon-halls-map.png` | фоновый рендер карты (64px/клетка)      |

ZIP собирается методом STORE (`fflate`, `level: 0`): PNG уже сжат,
контейнер нужен только для структуры. Код: `vtt/uvtt.ts`, `vtt/zip.ts`.

## Соответствие полей map.json нашей модели

| Поле UVTT       | Источник в MapModel                                                                                                    |
| --------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `format`        | константа `"0.3"`                                                                                                      |
| `resolution`    | `map_origin` = (0,0); `map_size` = width×height в клетках; `pixels_per_grid` = 64 (совпадает с PNG-экспортом)          |
| `line_of_sight` | замкнутые полигоны, собранные из стен-рёбер обходом планарных граней (`buildLineOfSight`), координаты в пикселях       |
| `portals`       | ТОЛЬКО двери-рёбра (`model.doors`): `bounds` — концы ребра, `closed` = `!door.open`, `rotation` 90 для N/S и 0 для E/W |
| `lights`        | `model.lights`: `position` — центр клетки в пикселях; `range` = radius как есть (в клетках); `color` — hex             |
| `environment`   | дефолты: `ambient_light` #ffffff, `ambient_intensity` 0.4                                                              |

### line_of_sight: как стены превращаются в полигоны

Стены хранятся как рёбра клеток `{ x, y, side }`. `buildLineOfSight`
обходит планарные грани графа рёбер (правило «первое свободное направление
против часовой после обратного»):

- внутренние грани (комнаты) получают положительную площадь и попадают в
  результат — **межкомнатные перегородки остаются контурами**, обзор сквозь
  них не проходит;
- внешняя грань отбрасывается знаком площади;
- висячие цепочки дают вырожденные грани нулевой площади и отбрасываются;
- дверь НЕ вырезает дыру в контуре комнаты — проём обеспечивается порталом.

## Ограничения

- **Только square-сетка**: формат описывает прямоугольные клетки. На гексах
  кнопка задизейблена с подсказкой, `exportMapToUvtt` дополнительно бросает
  RangeError (defense-in-depth).
- **Физика света не считается**: экспортируется только источник
  (позиция/радиус/цвет); освещение считает VTT-платформа.
- **Легаси-объект `door`** из каталога объектов — декорация (спрайт/цвет на
  клетке). В portals попадают ТОЛЬКО двери-рёбра из инструмента Door.
- Спрайтовый режим отображения применяется к PNG-рендеру так же, как в
  Export PNG (без атласа — цветной режим).

## Ручная проверка импорта (при изменениях формата)

1. Откройте карту с комнатой, перегородкой, дверью (открытой и закрытой) и
   парой источников света.
2. Export UVTT → сохраните `.uvtt`.
3. Foundry: модуль импорта .uvtt → импортировать → проверить: фон совпадает,
   стены блокируют движение/зрение, перегородка между комнатами блокирует
   зрение, закрытая дверь непроходима, открытая проходима, источники света
   на местах.
4. Roll20 (Pro): та же карта через импорт .uvtt, те же проверки.
5. Эталонный образец формата — `.uvtt`, экспортированный из Dungeondraft или
   DungeonFog; при расхождениях править `buildMapJson` по образцу, а не
   наоборот.
