# Dev Workflow — Чертоги подземелий

## Контекст

Веб-редактор батлмапов для D&D. Весь код во `frontend/` (React + TS + Vite),
бэкенда нет. Главный источник правды о проекте — `AGENTS.md` в корне репозитория.

**Состояние (обновлять по мере продвижения):**
Этапы 1–6 (редактор, генератор, гексы, спрайты, VTT-интеграция,
печать SVG/PDF через `editor/print/`) завершены полностью.
Следующий этап выбирает автор вручную (этапы 7+ в roadmap).

## Перед началом работы

1. Прочитай `AGENTS.md` (стек, конвенции, архитектурные правила, Git-процесс).
2. Перед работой с кодом `frontend/` прочитай `docs/frontend-guidelines.md`
   (паттерны обязательны: однонаправленный поток, иммутабельная модель,
   слои app/editor/generator/shared; исключение composition-root для EditorPage).
3. Открой `docs/roadmap.md` — работай по первому незакрытому пункту
   текущего этапа, если пользователь не указал иное.
4. Порядок этапов выбирает автор — не переходи к следующему этапу сам.
5. Работа ведётся в ветке этапа (`stage/<номер>`); слияние в `main` —
   только после выполнения всех условий «Git-процесса» в AGENTS.md.

## Команды (выполнять в `frontend/`)

```powershell
npm run dev        # dev-сервер http://localhost:5173
npm run test:ci    # тесты, один прогон (запускать ПЕРВЫМ)
npm run lint       # oxlint
npm run format     # Prettier
npm run build      # сборка + проверка типов tsc
```

## Перед завершением задачи

1. Прогони проверки В ПОРЯДКЕ: тесты → lint → build (в `frontend/`).
2. Пройди `docs/quality-checklist.md` по затронутым разделам и исправь
   найденное в той же сессии. Для генераторов — секция «Генераторы».
3. Для значимых изменений вызови сабагента-ревьюера `@reviewer`.
   При FAIL исправь замечания и вызывай повторно — не более 5 вызовов
   `@reviewer` суммарно на задачу; после пятого FAIL остановись и сообщи автору.
4. Отметь закрытый пункт roadmap `[x]`.

Коммит делай только по явной просьбе пользователя. Сообщение коммита —
короткое, в повелительном наклонении («Add brush tool», без точки в конце).

## Правила кода

- TypeScript strict, `any` запрещён; файлы компонентов `PascalCase.tsx`, остальные `camelCase.ts`.
- Стили — CSS Modules (`*.module.css`), цвета через переменные из `src/index.css`;
  inline-стили только для динамики canvas и data-driven значений палитры.
- Тексты интерфейса — ТОЛЬКО через i18n (`useTranslation`), ключи добавлять
  сразу в `ru.json` и `en.json`. Русский текст в JSX — ошибка.
- Модель карты не зависит от DOM/Canvas; команды иммутабельны, no-op не пишут историю.
- Комментарии — только «почему», не «что».

## Установленные паттерны (следуй им)

- **Формы**: чистый `parseXxxForm(state)` рядом с компонентом (не экспорт
  из .tsx), строгий парсинг (пустое/hex/exponent → null); кнопка блокируется
  до dispatch; авторитетная валидация остаётся в домене.
- **Pointer-инструменты**: хуки возвращают `handlers`, объединяются через
  `mergePointerHandlers()` — НИКОГДА не спредить два набора подряд
  (второй затирает первый).
- **Общий хелпер события**: `useCellFromEvent(canvasRef, viewportRef)` —
  параметр `ClientPoint = Pick<…,'clientX'|'clientY'>`, не полный event.
- **Refs в событиях**: чтение `ref.current` только внутри обработчиков/эффектов;
  «latest ref» паттерн обновляется через useEffect, не в рендере.
- **Тесты**: интеграционные тесты должны быть дискриминирующими (ловить
  конкретную регрессию, см. stale-id тест EditorPage); стабы jsdom
  (ResizeObserver, matchMedia) живут в `src/test/setup.ts`; язык i18n в
  тестах зафиксирован en там же.
- **Hex-геометрия рендера**: мировые координаты клеток — только через
  `editor/render/gridGeometry.ts` (`cellCenterAt` нормализована к [0..bounds],
  origin-сдвиг гексов зашит внутрь); размеры холстов/лимиты — из
  `mapPixelBounds` с `Math.ceil` (canvas.width целочисленный); culling —
  `visibleCellRange` (запас 2 клетки, пустой диапазон за картой обязателен);
  полигоны трассировать только `traceCellPolygon` (с `closePath` — иначе
  stroke теряет ребро).
- **Hex hit-test**: `screenToCell(viewport, x, y, gridType)` — hex-ветка
  обязана зеркалить origin-нормировку `cellCenterAt` (сдвиг −(√3/2·s, s)
  для pointy / −(s, √3/2·s) для flat); константы повторяются в трёх местах
  (mapPixelBounds, cellCenterAt, screenToCell) и охраняются round-trip
  тестом по всем клеткам и viewport'ам; `gridType` в deps `useCallback`.
- **Известные ловушки vitest**: `fireEvent.pointercancel` отсутствует —
  собирать через `Object.assign(new Event('pointercancel'), {...})`.
